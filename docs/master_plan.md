# Portfolio Master Plan

## Section 1 — Portfolio Sections Blueprint

Urutan section dari atas ke bawah yang paling efektif untuk software engineer di 2026:

---

### 1. Hero / Above the Fold
**Tujuan:** First impression. Visitor memutuskan dalam 3 detik apakah mau scroll atau tidak.
**Konten:**
- Nama + title singkat (misal: "Full-Stack Engineer · TypeScript · AI")
- One-liner value proposition (bukan deskripsi diri, tapi nilai yang kamu bawa)
- CTA utama: "See My Work" atau "Download CV"
- Status availability (Open to work / Not available)

---

### 2. About / Who I Am
**Tujuan:** Membangun koneksi personal dan kepercayaan. Recruiter/client ingin tahu siapa kamu di balik kode.
**Konten:**
- Narasi singkat (3–4 kalimat): background, fokus, dan apa yang drives kamu
- Tech stack utama (ikon + nama, bukan paragraf panjang)
- Nomor ringkas: tahun pengalaman, project selesai, dll.

---

### 3. Featured Projects
**Tujuan:** Bukti nyata kemampuan. Ini adalah bagian paling penting.
**Konten per project (maks 3–4 project pilihan):**
- Nama + tagline satu kalimat
- Tech stack yang dipakai
- Problem yang diselesaikan (bukan fitur list)
- Screenshot / demo GIF / live link
- Link ke GitHub atau case study

---

### 4. Experience / Timeline
**Tujuan:** Menunjukkan trajectory karir dan kredibilitas profesional.
**Konten:**
- Posisi, perusahaan, durasi
- 2–3 bullet impact per peran (angka jika ada: "reduced load time by 40%")
- Jangan copy-paste job description

---

### 5. Skills / Tech Stack
**Tujuan:** Memudahkan recruiter/ATS untuk mencocokkan profil dengan kebutuhan mereka.
**Konten:**
- Kelompokkan: Frontend / Backend / DevOps / Tools
- Jangan listing semua — prioritaskan yang benar-benar kamu kuasai
- Visual: ikon + nama, bukan progress bar (progress bar tidak bermakna)

---

### 6. Open Source / Contributions (opsional tapi bernilai tinggi)
**Tujuan:** Menunjukkan inisiatif dan kemampuan bekerja di codebase orang lain.
**Konten:**
- Repo yang pernah di-contribute
- PR yang merged di project populer
- Tools / library yang kamu buat sendiri

---

### 7. Writing / Blog (opsional)
**Tujuan:** Membuktikan kedalaman pemahaman dan kemampuan komunikasi teknis.
**Konten:**
- 3–6 artikel terbaik dengan judul + satu kalimat ringkasan
- Link ke platform (Medium, dev.to, atau blog sendiri)

---

### 8. Contact / CTA Akhir
**Tujuan:** Mengkonversi visitor menjadi leads. Jangan biarkan mereka pergi tanpa tindakan.
**Konten:**
- Kalimat pembuka yang engaging (bukan "Feel free to contact me")
- Form singkat ATAU link langsung ke email
- Link sosial: LinkedIn, GitHub, Twitter/X
- Response time expectation: "I reply within 24h"

---

## Section 2 — Copywriting

> Profil: Backend & DevOps Engineer · Golang, NodeJS, React/NextJS, AWS, GCP
> Domain: EduTech, Fintech, Web3, Backoffice/CMS/ERP
> Tone: Kasual tapi profesional, percaya diri

---

### 1. Hero / Above the Fold

**Headline (pilih salah satu):**

| # | Opsi | Karakter |
|---|------|----------|
| A | `Backend Engineer Who Keeps Systems Alive at Scale` | Tegas, ownership |
| B | `I Build the Engines Behind Products People Rely On` | Evocative, impact |
| C | `Golang · Cloud · Systems That Don't Break at 3am` | Spesifik, relatable |

> Rekomendasi: **Opsi B** — universal, memorable, tidak perlu tahu Golang pun langsung ngerti value-mu.

**Sub-headline:**
> "I'm a backend & DevOps engineer specializing in building scalable systems for Fintech, EduTech, and Web3 products — from API design to cloud infrastructure on AWS and GCP."

**CTA Buttons:**
- Primary: `See My Projects`
- Secondary: `Download CV` atau `Let's Talk`

**Status badge:**
- `🟢 Open to Opportunities` / `🔴 Not Available`

---

### 2. About / Who I Am

**Narasi (3–4 kalimat, siap pakai):**
> "I'm a software engineer with a backend-first mindset. I spend most of my time designing APIs, wiring up cloud infrastructure, and making sure distributed systems behave themselves. I've shipped products across Fintech, EduTech, Web3, and enterprise tools — usually the kind of systems where downtime isn't an option.
>
> I write Go for performance, Node when speed matters more than overhead, and reach for React/Next.js when the frontend can't wait for someone else."

**Stats (isi angka sesuai realita kamu):**
- `X+ Years Experience`
- `X+ Projects Shipped`
- `X+ Domains: Fintech · EduTech · Web3 · Enterprise`

---

**Section header:**
> "Things I've Built"

**Sub-header (opsional):**

**Template tagline per project:**
```
[Nama Project]
[Satu kalimat: problem + solusi + impact]

```

**Contoh tagline (placeholder — ganti dengan project asli):**

- *"Real-time learning analytics platform for 10k+ students built on event-driven architecture."*

---

### 4. Experience / Timeline

**Section header:**
> "Where I've Worked"

**Formula bullet impact (gunakan ini, bukan job desc):**
```
[Action verb] + [what you built/did] + [measurable result jika ada]
```

**Contoh:**
- *"Redesigned deployment pipeline, cutting release time from 2 hours to 15 minutes."*
- *"Built multi-tenant API serving 3 enterprise clients with isolated data and SLA uptime 99.9%."*
- *"Led backend migration from monolith to microservices, reducing infrastructure cost by 30%."*

**Section header:**
> "What I Work With"

**Grouping copy:**
| Kategori | Label |

| Backend | `Backend` |

### 6. Open Source / Contributions

**Section header:**
> "In the Wild"

**Sub-header:**
> "Code I've written that's now running on other people's machines."

---

### 7. Writing / Blog

**Section header:**
> "Things I Figured Out (and Wrote Down)"

**Sub-header:**
> "Technical deep-dives, lessons from production, and the occasional strong opinion."

---

### 8. Contact / CTA Akhir

**Section header:**
> "Let's Build Something"

**Opening copy (jangan "feel free to reach out"):**
> "Got a project that needs solid backend architecture, or just want to talk about distributed systems at 2am? Either way, I'm in."

**CTA Button:**
- `Send Me a Message`
- `Book a Call` (jika pakai Calendly)

## Section 3 — Project Descriptions

> Format: Opening hook · Fitur utama (2–3 kalimat) · Penutup tech/hasil
> Tone: Profesional tapi conversational — seperti kamu yang cerita, bukan press release.

---

### terampil.com
**Education Platform · Node.js · Next.js · React Native · AWS EC2 · S3 · PostgreSQL · GraphQL**

> *Building an e-learning platform is straightforward — until you have to make sure videos never buffer and content never leaks.*
>
> Terampil is a Udemy-style learning platform where students can access courses across web and mobile. I built the full backend with Node.js/Express and GraphQL, handled video delivery through AWS S3 with access control to prevent unauthorized sharing, and tuned the infrastructure on EC2 to keep streaming smooth under load. The hard part wasn't building the player — it was making sure content was protected without ruining the experience for legitimate users.

---

### indofund.id
**P2P Fintech · Peer-to-Peer Lending · Node.js · MongoDB · React · Redis**

> *In fintech, a bug isn't just a bug — it's someone's money going somewhere it shouldn't.*
>
> Indofund is a B2B peer-to-peer lending platform connecting lenders and borrowers. I built the core transaction system with strict money-movement logic to ensure every disbursement, repayment, and fee calculation was deterministic and auditable. I also integrated with third-party fintech providers for OJK regulatory reporting — which meant mapping our data model to external schemas and handling async reconciliation without losing records.

---

### nobi
**Crypto Trading & Investment · Golang · gRPC · REST · React Native · MySQL · Redis · RabbitMQ**

> *When your app moves real money 24/7, "close enough" in your math is not an option.*
>
> Nobi is a crypto trading and staking platform for retail investors. I built the staking ledger system in Go — the component that tracks every user's staked assets, calculates rewards with high-precision arithmetic, and reconciles balances across async events flowing through RabbitMQ. Exposing both gRPC and REST APIs let us serve the mobile app and internal services without maintaining separate backends.

---

### Snap Together
**Event Photo Sharing · React Native · Node.js · MongoDB · Redis · AWS S3**

> *Remember printing photos at events and handing them out? This is that — but instant, and everyone leaves with everything.*
>
> Snap Together lets event organizers invite guests into a shared photo space. Attendees snap and upload throughout the event, and anyone can pull all photos to their phone with a single tap. The trickiest part was storage management at scale — keeping upload pipelines fast, serving images without lag, and using Redis caching to avoid hammering S3 on every gallery load.

---

### hygear
**Fitness Super App · React Native · Node.js · MongoDB · React · Redis**

> *Most fitness apps track your workouts. Hygear connects to the actual equipment you're using.*
>
> Hygear is a worldwide fitness super app that bridges real gym hardware with mobile software. I handled the backend data layer for workout sessions — collecting real-time device signals, calculating calorie burn with formula-based logic, and keeping the live data feed responsive through WebSocket connections and Redis. I also built the backoffice in React for the ops team to manage content and equipment configurations.

---

### dimatour
**Umrah & Hajj Travel · React · Firebase · Serverless**

> *A travel company's website is often the first — and only — thing a prospective customer sees before deciding to trust you with their pilgrimage.*
>
> Dimatour is the company profile website for a specialized Umrah and Hajj tour operator. Built fully serverless using React and Firebase, which meant no backend to maintain and near-zero infrastructure overhead. The challenge was making sure a serverless setup felt stable and fast for users who may not be tech-savvy — proper Firestore query structure and CDN delivery made that possible.

---

### halotamu
**Digital Visitor Management · Golang · Next.js · PostgreSQL**

> *The visitor logbook at most offices is still a piece of paper. Halotamu fixes that.*
>
> Halotamu is a digital check-in/check-out system for residential complexes, offices, and apartments. Guards and receptionists can log visitors, track entry and exit times, and keep a searchable record — all from a clean web interface built with Next.js. The Go backend keeps things lean and fast, with PostgreSQL handling the audit trail that makes the data actually useful for security and reporting.

---

## Prinsip Desain untuk Portfolio 2026
- **No fluff:** Setiap kata harus earned. Hapus semua kalimat klise.
- **Mobile-first:** 60%+ traffic datang dari mobile.
- **Fast:** Core Web Vitals harus hijau. Portfolio lambat = sinyal buruk.
- **Dark mode default** atau support both: mayoritas dev prefer dark.
- **Accessible:** Minimal WCAG 2.1 AA compliance.
